# Техническое задание — Приложение по обучению английскому языку

> Источник: `docs/sources/Проект_приложение_по_обучению_английскому_языку.docx` (разделы 1–2.3, дословно).
> Статус: зеркало. При расхождении верен docx.

## 1. Описание проблемы

С выходом на международный рынок у Т возникла потребность в повышении квалификации сотрудников в области английского языка. Одними из важных компонентов изучения языка являются увеличение словарного запаса и закрепление грамматической базы. В качестве вспомогательного инструмента обучения сотрудников предлагается разработать приложение, содержащее функционал для закрепления словарного запаса в английском языке. Приложение призвано развить знания языка и повысить квалификацию коллег для работы на международном рынке.

## 2. Концепт идеи

Проект является трехкомпонентной системой — бэкэнд, веб-приложение и админка. Веб-приложение должно содержать основной функционал для обучения. Администрирование данных, хранящихся на бэкэнде, должно производиться через админку.

### 2.1 Описание веб-приложения

Приложение должно быть максимально простым. Количество кликов до получения контента — 0: открыл и уже начал учить слова.

Основной функционал приложения состоит из фич:

| Фича | MVP |
|---|---|
| Модуль авторизации | ✅ |
| Модуль обучения — карточки со словами на главном экране | ✅ |
| Модуль статистики — графики, данные о количестве заученных слов | ✅ |
| Настройки | ✅ |
| Профиль пользователя (редактирование имени, фамилии, фотографии) | ❌ (не в MVP) |
| Лидерборд (кто больше слов выучил за неделю/месяц) | ❌ (не в MVP) |
| Content of the day (абзац из книги + случайное видео на YouTube раз в день) | ❌ (не в MVP) |
| Пуши и диплинки | ❌ (не в MVP) |
| Примеры использования слов из Google translate / Яндекс переводчика | ❌ (не в MVP; надо смотреть, что можно вытащить, но точно не в MVP) |

Пользовательский интерфейс должен быть адаптивным, но mobile-first. Также стоит заложить поддержку PWA (не в MVP). При продумывании дизайна рекомендуется опираться на принципы Material Design.

#### 2.1.1 Модуль авторизации

Пользователю важно быть авторизованным, чтобы сохранять свои успехи на бэке и идентифицировать себя в таблице лидеров в соревновании.

**Флоу авторизации:**

1. Пользователь открывает приложение, попадает на сплэш-скрин.
2. Если пользователь не был авторизован ранее, он редиректится на экран авторизации.
3. На экране авторизации пользователь вводит свою рабочую почту.
4. На сервер отправляется запрос на авторизацию.
5. Сервер отправляет 6-значный код на почту; приложение получает респонс, что процесс авторизации начат, и перекидывает пользователя на экран ввода кода.
6. Пользователь вводит код с почты и отправляет запрос на сервер вместе с передачей почты.
7. Сервер возвращает 30-дневный токен; приложение его запоминает и использует в каждом запросе в авторизованной зоне.
8. Пользователя редиректит на основной экран.

Пользователь должен проходить авторизацию каждые 30 дней для сохранения безопасности доступа к приложению.

**Экран ввода электронной почты** должен состоять из одного поля для ввода почты и кнопки «Войти». Расположение, оформление и выбор цветов остается на усмотрение дизайнера.

**Экран ввода кода** должен содержать поле для ввода 6-значного кода. Отправка кода может происходить либо по кнопке «Отправить код», либо при вводе последнего символа кода. Для реализации можно использовать готовые решения, например [input-otp](https://www.npmjs.com/package/input-otp). Также на экране должна быть кнопка повторного запроса кода на случай, если что-то пошло не так. Кнопка должна становиться доступной для нажатия спустя 60 секунд после захода на экран.

#### 2.1.2 Модуль обучения

Модуль обучения является основным модулем и состоит из одного экрана. На этот экран можно попасть либо через экран ввода кода, либо через сплэш-скрин.

На экране появляются карточки со словами, которые можно убрать вправо или влево (манипулировать только кнопками — в MVP; drag'n'drop — если команда успевает). Типы карточек и их экшны «влево»/«вправо»:

| Тип карточки | Экшн | Экшн |
|---|---|---|
| Новое слово | «Я уже знаю это слово» | «Я не знал этого слова» |
| Слово в ротации (английский → русский) | «Я запомнил это слово» | «Я не запомнил это слово» |
| Слово в ротации (русский → английский) | «Я запомнил это слово» | «Я не запомнил это слово» |

Выбрав словарь в настройках (может быть и словарь по умолчанию), пользователь начинает обучение. Словарь состоит из пар английских (с транскрипцией) и русских слов; эта информация отобразится на карточках.

Система подбрасывает пользователю новое английское слово из словаря, отображая его английское написание и транскрипцию на карточке нового слова. Перевод на русском скрыт и открывается по нажатии кнопки «Показать слово» (текст кнопки можно заменить иконкой глаза).

- Пользователь нажимает «Я уже знаю это слово» — слово больше не встретится при обучении.
- Пользователь нажимает «Я не знал этого слова» — слово попадает в ротацию.

**Ротация.** Слово, находящееся в ротации, повторяется для пользователя 8 раз: через 5 минут, через 1 час, через 1 день, через неделю, через месяц и через 3 месяца (назовем это этапами повторения). Пользователь должен подтвердить, что он запомнил слово, 8 раз нажатием кнопки «Я запомнил это слово». После прохождения 8 этапов повторений слово считается выученным и больше не встречается.

Если пользователь нажимает «Я не запомнил это слово», оно повторяется еще раз через 5 минут и через 1 час, а затем возвращается к следующему этапу повторения после того, на котором была нажата кнопка «Я не запомнил это слово».

> Примечание: лестница из 8 этапов: 5 мин → 1 час → 1 день → неделя → месяц → 3 месяца → 6 месяцев → 12 месяцев (решение D-03 в `walking-skeleton.md`).

По большому счету механизм ротации представляет собой формирование и обработку очереди из карточек разных типов. Приоритетными карточками в очереди являются те, которые уже в ротации и этап повторения которых уже наступил.

**Пример.** У пользователя в ротации 2 слова:
- *feel* — этап «повторить через неделю» — отмечено 7 января в 14:50;
- *sick* — этап «повторить через день» — отмечено 13 января в 13:40.

14 января оба слова попадают в список слов, которые уже можно показывать, и показывать их нужно в том порядке, в котором время возможности их показа наступило: сначала *sick*, затем *feel*. Когда эти два слова будут показаны и в ротации больше не останется слов, можно показывать новые слова.

**Вид карточек.** Карточки в ротации могут быть как с открытым английским словом и закрытым русским (перевести с английского на русский), так и наоборот (перевести с русского на английский). Это нужно, чтобы пользователь мог выстраивать связи в обе стороны. На обоих типах карточек есть кнопка «Показать слово», открывающая перевод. Тип карточки выбирается случайно при следующем повторении в ротации. Карточки новых слов всегда имеют тип «английский → русский». Номер этапа повторения можно вывести в верхнем углу карточки.

Также на карточках хотелось бы иметь примеры использования слов в предложениях. Нужно копать апишку Google translate или Яндекс переводчика. С гугла можно, но могут быть проблемы с предоставлением услуг сейчас. **Фича точно не идет в MVP.**

Кнопки действий с карточками можно разместить как на карточках, так и отдельно (на усмотрение дизайнера).

#### 2.1.3 Модуль статистики

На основном экране располагается кнопка открытия экрана статистики. По ее нажатии отображается статистика по словам:

- прогресс по выбранному словарю: сколько слов выучено до конца, сколько слов в ротации, сколько слов не попало в ротацию (их он уже знает), сколько слов осталось;
- количество выученных слов по дням (столбчатая диаграмма).

Сам экран статистики можно сделать в виде bottom sheet компонента, а график — с помощью пакета [recharts](https://www.npmjs.com/package/recharts).

#### 2.1.4 Настройки приложения

В настройках реализуются функции по управлению ротацией и словарями, а также выбор темы. Переход осуществляется по нажатии на кнопку на основном экране.

- Выбор словаря (скачивание + обновление с синхронизацией прогресса);
- Мануальное повторение уже выученных слов — запуск выученных слов в ротацию, по одному разу, без дальнейших переходов по этапам. Выученные слова идут наивысшим приоритетом и выключаются по нажатию кнопки (убираются из ротации). **Не в MVP**;
- Сброс данных по словарю / всех данных;
- Выбор темы (дневная/ночная).

#### 2.1.5 Модуль «Профиль пользователя» (не в MVP)

Приложение не предусматривает прямого взаимодействия между пользователями, поэтому модуль предельно простой: ввести (поменять) имя и фамилию, поставить фото профиля. Информация отображается в лидерборде.

Экран может быть открыт в виде bottom sheet: поле для фотографии, два редактируемых поля (имя и фамилия), одно нередактируемое поле для отображения электронной почты. Оформление кнопок «редактировать» и «сохранить» — на усмотрение дизайнера.

#### 2.1.6 Модуль «Лидерборд» (не в MVP)

Экран со списком сотрудников, выучивших наибольшее число слов в этом месяце. Первые 3 месяца лидерборд будет пустовать, в каждом последующем месяце — честное соревнование. В конце месяца определится победитель, который получит мерч или ачивку во внутрикорпоративной сети.

Каждая запись в списке состоит из 3 полей:

1. Номер (место);
2. Имя Фамилия (или электронная почта, если имя не указано);
3. Количество выученных слов с 1 числа текущего месяца.

Перед списком — заголовок и короткое описание лидерборда (должен быть указан месяц).

#### 2.1.7 Модуль «Content of the day» (не в MVP)

Экран, открывающийся по нажатии на кнопку на основном экране. В раздел может вести бадж, размещенный на кнопке. Экран — список из двух элементов:

1. **Абзац на английском** с переводом и указанием источника, например:

   > «Oh, how I wish I could shut up like a telescope! I think I could, if only I knew how to begin.» For, you see, so many out-of-the-way things had happened lately, that Alice had begun to think that very few things indeed were really impossible.
   > — "Alise in Wonderland", Chapter 1, Down the Rabbit-Hole
   >
   > «Ах, как бы я хотела складываться, как подзорная труба! Я думаю, смогла бы, если бы только знала, с чего начать.» Видишь ли, так много невероятных событий произошло в тот день, что Алиса начала думать, что лишь очень малая часть вещей была действительно невозможна.
   > — «Алиса в Стране чудес», Глава 1 «Вниз по кроличьей норе»

2. **Видео с контентом на английском** (желательно с субтитрами). В концепции: научпоп-видео с хорошей дикцией, вырезки из комедийных шоу и т.д.

Раздел помогает пользователю адаптироваться к художественному стилю текстов и прокачивать «слушание» и скоростное чтение (субтитров).

#### 2.1.8 Пуши и диплинки (не в MVP)

Необходимо иногда напоминать о том, что нужно зайти в приложение и выучить слова. Экшны для пушей:

- Новый content of the day;
- Ненавязчивое напоминание о том, что пора выучить несколько слов;
- Итоги лидерборда в конце месяца.

Диплинки желательно интегрировать для редиректа на приложение через посты для сотрудников в корпоративной сети или на почте.

### 2.2 Описание серверной части

Серверная часть должна содержать несколько фич с доступом по правам — администратор, модератор, пользователь.

**Фичи для пользователя:**

- Авторизация;
- Получение данных о словаре (скачивание);
- Сохранение прогресса по словарю (синк прогресса изучения слов на девайсе с бэком);
- Получение статистики прогресса по словарям;
- Редактирование имени, фамилии, фото профиля (не в MVP);
- Получение данных о лидерборде (не в MVP);
- Получение данных в content of the day (не в MVP).

**Фичи для модератора (в админке):**

- Авторизация модератора в админке;
- Просмотр статистики прогресса у пользователей;
- Обеспечение доступа к словарям (получение/редактирование/сохранение словарей);
- Просмотр лидерборда (не в MVP);
- Просмотр и редактирование данных пользователей (не в MVP);
- Редактирование контента в Content of the day (не в MVP).

**Фичи для администратора** — такие же, как для модератора, за исключением возможности управлять привилегиями.

> Примечание ADR-003: диаграммы фиксируют управление ролями как админ-фичу (см. `docs/diagrams/uc-1-context.md`); в ТЗ это выводится из фразы «за исключением возможности управлять привилегиями».

### 2.2.1 Данные

Примерное описание таблиц с данными для хранения их в БД. В процессе проектирования бэкэнда допускается, что данные могут быть изменены на усмотрение проектной команды.

| Сущность | Описание полей |
|---|---|
| **Слово** | `id: Int`, `vocabulary_id: Int`, `word: String`, `translation: String`, `transcription: String`, `type: Enum("Существительное", "Прилагательное", "Глагол", "Местоимение", "Наречие")` |
| **Словарь** | `id: Int`, `name: String`, `words_count: Int` |
| **Пользователь** (MVP) | `id: Int`, `email: String` |
| **Пользователь** (не в MVP) | `id: Int`, `email: String`, `first_name: String`, `last_name: String`, `photo_url: String` |
| **Статистика** | `id: Int`, `user_id: Int`, `vocabulary_id: Int`, `already_known: Int`, `in_progress: Int`, `memorized: Int` |
| **Лидерборд (запись)** — не в MVP | `id: Int`, `leaderboard_id: Int`, `position: Int`, `user_id: Int`, `memorized_words_count: Int` |
| **Лидерборд (таблица)** — не в MVP | `id: Int`, `date: Date` |
| **Content of the day** — не в MVP | `id: Int`, `eng_text: String`, `rus_text: String`, `video_url: String` |

### 2.2.2 Авторизация (с точки зрения сервера)

Флоу авторизации описан в п. 2.1.1. От сервера требуется реализовать работу с 6-значным кодом и отправку токена.

1. Пользователь запрашивает авторизацию;
2. Сервер генерирует код и отправляет на почту пользователя;
3. Пользователь отправляет пришедший на почту код серверу;
4. Сервер сравнивает ожидаемый код с переданным и в случае успеха отправляет токен пользователю. Все дальнейшие запросы должны быть выполнены в авторизованной зоне.

### 2.3 Описание админки

Панель администратора содержит функционал для работы с контентом приложения и данными пользователей.

В админке должны присутствовать следующие фичи:

- Авторизация модератора (администратора) в админке (так же по коду, как и авторизация в веб-приложении);
- Просмотр статистики прогресса у пользователей + выгрузка в xls;
- Работа со словарями (получение из xls / редактирование / сохранение / выгрузка в xls);
- Просмотр и редактирование данных пользователей (для администраторов — наделение пользователя правами модератора/администратора; в MVP — только просмотр, не в MVP — редактирование данных ФИО/фото);
- Просмотр лидерборда (не в MVP);
- Редактирование контента в Content of the day (не в MVP).

При продумывании дизайна рекомендуется использовать подходы Material Design. Конкретных пожеланий по дизайну в плане элементов и представления данных нет — реализация на усмотрение проектной команды (с согласованием с заказчиком в процессе выполнения работы).
